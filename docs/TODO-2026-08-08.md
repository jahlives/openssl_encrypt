## RESUME HERE (HISTORICAL) — Flutter toolchain (container is being restarted to install it)

State as of the end of the 2026-08-09 session. The container is being
rebuilt/restarted specifically to add a Flutter toolchain, because every
remaining GUI item needs Dart that can be compile-checked.

### What the container had (investigated, not assumed)

- Debian 12 bookworm, x86_64, ~104 GB free — space is not a constraint.
- **Network works**: pub.dev and github.com both reachable (200).
- Present: `gcc`, `git`, `curl`, `tar`, `bash`, `which`, `mkdir`, `rm`,
  and Python with `lzma` (so a `.tar.xz` can be extracted without the
  `xz` binary).
- Missing: `flutter`, `dart`, `clang`, `cmake`, `ninja`, `pkg-config`,
  and the shell tools `file`, `unzip`, `xz`, `zip`.
- **uid 1000, no sudo**, and `/var/lib/apt/lists` is empty — so
  `apt-get update` and any install must happen at image-build time or as
  root. The Flutter SDK itself is user-space and can be installed without
  root once the prerequisites exist.

### What to install

Tier 1 — static analysis and the Dart test suite. **This is the tier that
unblocks the work:**

```
apt-get update && apt-get install -y file unzip xz-utils zip
```

Tier 2 — only needed for a full `flutter build linux`:

```
apt-get install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev
```

Tier 2 buys little here: the container has no display, so even a successful
build could not RUN the GUI without something like `xvfb`. Compile-checking
is the real gain and `flutter analyze` provides most of it.
