# Remaining work after the 2026-08-08 audit

Every open issue was checked against the code, not against the changelog —
that distinction mattered: the audit found two changelog entries describing
GUI controls that do not exist (gitlab#198), and it also corrected my own
first impression that gitlab#151 was unimplemented when it is simply built a
different way than the flag name suggested.

51 issues were open when the audit started; 19 were already implemented and
have been closed with evidence. These 32 remain, grouped by what they are
and ordered by what I would do first.

## 1. Correctness bugs with a user-visible failure

Highest value: each one is something that silently does the wrong thing.

| Issue | What is wrong | Why it matters |
|---|---|---|
| **#149** | Recovery passphrases bypass the password-strength policy | A recovery slot is an **additional wrapping of the same file key**, so a weak passphrase is a weak key for the whole file. The strongest primary password does not help. |
| **#179** | Seven documented commands (`create-usb`, `verify-usb`, the five `*-plugin`) route to a subparser that does not exist | Documented commands that cannot run. Verified pre-existing. |
| **#177** | Global-flag preprocessing ignores `--` and can take an option *value* as the command | `-i --debug` style argv can be misread; the same preprocessing already caused gitlab#171. |
| **#174** | Confirmation prompts go to stdout while their warning text goes to stderr | Redirecting stdout hides the question but not the warning, so a user can be prompted invisibly. |
| **#176** | `install-dependencies --yes` still rejected; `main()`'s routing skip-set is a hand-maintained duplicate | The duplicate list is the same defect class as gitlab#171's `SUBPARSER_COMMANDS` drift. |
| **#156** | keyring store/load never runs when the password comes from the environment | Silently does nothing; the GUI depends on the environment path, which is why gitlab#153 deliberately did not expose the flags. |
| **#160** | `verify-signature --json`: a pinned mismatch emits no JSON; the authenticated algorithm is not exposed | A machine-readable channel that goes silent on the security-relevant outcome. |
| **#168** | `analyze-config` reads KDF/cipher keys its own parser never sets | Advice derived from values that are always absent. |
| **#166** (part) | `analyze-config` scores argparse defaults and misreports PQC | Same area as #168; do them together. |
| **#167** (part) | `template compare --format json` ignores the flag | Verified: prints the human report, emits nothing on stdout. `template list` is fixed. |

## 2. GUI surface that exists on one side only

The defect class the argv lint was built for, mirrored. **#198 is the
umbrella** and should be done first, because the lint it proposes would find
the rest mechanically.

- **#198** — four `cli_service.dart` parameters (`pqcKeyfile`,
  `useXorComposition`, `parallelKdf`, `kdfWorkers`) have **no callers**, so
  the Encrypt-tab controls the changelog describes are unreachable.
  Proposes the mirror check: every parameter `cli_service` accepts must have
  at least one caller.
- **#141** — `CLIService.checkPassword()` is implemented and nothing calls
  it; there is no live strength indicator.
- **#151/#153 residue** — both issues' *service* halves landed; see #198.
- **#161, #163** — identity flags (`--no-touch`, `--allow-key-change`, PIV
  slot). #163 is the CLI half and blocks #161.
- **#155** — Batch Operations parity (KDF/hash/HSM/pepper/steganography
  panels). HSM and pepper are wired on the Encrypt tab already.
- **#165, #162** — analyze-config screen and telemetry opt-out; #162 (no
  machine-readable output for `analyze-security`,
  `smart-recommendations`, `telemetry status`) blocks it.
- **#192, #193, #194** — 1.5.x GUI: the last steganography item, and the
  pepper/integrity CLI surface the GUI already calls (registered in the argv
  lint's KNOWN_BROKEN so they are visible, not silent).

## 3. Hardening and follow-ups

- **#117** — hsm+remote pepper concatenation enters the v14 TLV seed as one
  unprefixed field.
- **#118** — `_parse_metadata`'s no-validator fallback lacks the
  format_version type/range guard.
- **#119** — legacy-retry `ValueError` swallows exception chaining in
  `pqc.py`.
- **#120** — adapter KEM decrypt calls `cipher.decrypt(nonce, ct, aad)`
  uniformly; aes-siv would `TypeError`.
- **#147** — security review follow-ups: encode edges, redaction parity,
  `-p` warning.
- **#169** — template self-asserted security score is the sort key;
  unbounded `hash_config`; secret-to-disk in create.
- **#170** — video steganography options are dead surface; MP4 advertised
  but absent. Blocks the #167 GUI half.
- **#175** — GUI `_runCLICommandWithStdin` writes and closes stdin before
  draining stdout/stderr (classic deadlock shape on a large payload).
- **#180** — credential-channel follow-ups: late consume on the encrypt
  path, `info` cannot *request* the credential, the fd blank check
  duplicates the rule.
- **#182** — `generate-password` still claims to clear the screen; the
  orphan-password NOTE misses the `return 1` paths; `realpath` does not
  resolve hardlinks.

## Suggested order

1. **#198** — build the has-a-caller lint. It is cheap, it uses the same AST
   machinery as the argv lint, and it converts "which GUI features are real"
   from an audit into a test. Everything in group 2 gets easier afterwards.
2. **#149** — smallest change with the most direct security consequence.
3. **#179**, then **#177**/**#176** — one area, all argv routing, and #176's
   duplicate list is the same drift that produced #171.
4. **#168 + #166 + #167** — `analyze-config`/`template` cluster.
5. Group 3 hardening, in issue order.

## Not tracked as issues, but pending

- **No Dart has ever been compiled or `flutter test`-ed here** — there is no
  Flutter toolchain in this container. Every GUI change this session is
  argv-verified against the real argparse tree but not compile-checked. Run
  `cd desktop_gui && flutter analyze && flutter test`.
- **The signed source-integrity manifest is stale.** `crypt_cli.py`,
  `crypt_cli_subparser.py`, `crypt_core.py`, `cli.py` and `__main__.py` all
  changed, so `verify-integrity` reports a false tamper until the manifest is
  regenerated and re-signed with the release key.
- **Eight GHSA-backed advisories are drafted and held** (gitlab#128–#134,
  #136, plus the earlier ones). They are fixed and closed but deliberately
  still confidential: PyPI's newest release is **1.4.8**, so publishing now
  would disclose flaws affecting every released version with no fixed release
  to move to. At 1.4.9 / 1.5.0 release: publish each GHSA, drop
  confidentiality, and file the public GitHub mirrors.
